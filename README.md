Нативный iOS-компаньон для сервиса SanPlan на базе технологии Apple **AlarmKit** (iOS 26+). Приложение устанавливает полноценные системные будильники iOS, которые звучат на экране блокировки устройства даже при выключенном экране и закрытом приложении.

## 1. Архитектура и безопасность

- **Настоящие системные будильники:** приложение использует официальный API Apple AlarmKit (`AlarmManager.shared`), а **не** имитацию через push-уведомления, WebAudio, VoIP, PushKit или CallKit.
- **Единая 4-вкладочная навигация и постоянный WKWebView:**
  - Нативный док содержит 4 равноправные вкладки в едином порядке: **Календарь**, **Запись**, **Будильники**, **Настройки**.
  - Экземпляр `WKWebView` смонтирован **постоянно** в `ZStack` и никогда не выгружается при переключении нативных табов. Благодаря этому сохраняются активная запись с микрофона, черновики, web audio измерения и сессия авторизации.
  - Веб-интерфейс получает защищенный флаг `window.SanPlanNative = true` и класс `.native-shell`, скрывающий дублирующий веб-док и лишние шапки.
- **Информативный нативный экран будильников:**
  - Отображает собственные активные сигналы, сгруппированные по планам и названиям.
  - Блок **Ближайший сигнал (Next-Signal Prominent)** выделяет ближайшее срабатывание с точным временем события, смещением и часовым поясом.
  - Честные состояния: авторизация, загрузка, отсутствие планов, ошибки связи, предупреждения лимитов. Сырые UUID не показываются пользователю.
  - Диагностика через 1 минуту вынесена в свернутый блок и не мешает основному экрану.
- **Надежная сверка с системой (Reconciliation) по спецификации Apple:**
  - Согласно официальной документации Apple, однократные будильники после срабатывания или отключения пользователем автоматически удаляются системным демоном. Координатор распознает штатное отсутствие сигнала и удаляет запись из локального реестра без генерации ложных ошибок.
  - Недостающие будущие будильники восстанавливаются без дублирования.
  - Если отмена будильника возвращает ошибку, координатор запрашивает свежий снимок системы: если будильник уже отсутствует — запись удаляется; если всё ещё существует или снимок не удался — запись сохраняется для повторной попытки, а пользователю выводится понятное сообщение с названием задачи.
  - Ошибки перечисления системных будильников **никогда** не приводят к очистке реестра.
  - Приложение удаляет и изменяет **исключительно собственные** будильники SanPlan, не затрагивая личные будильники пользователя.
- **Информативные системные заголовки:**
  - Системный сигнал на экране блокировки содержит понятный заголовок вида: `«Название задачи — 15 окт, 14:00 (за 15 мин.)»`.
  - Поле `metadata.targetDate` хранит точное время исходного события (`eventDate`), а не время срабатывания будильника.
- **Детерминированные идентификаторы UUID:** формируются на базе первых 16 байт хэша SHA-256 от комбинации `id задачи + дата/время события (UTC) + смещение в минутах`.
- **Политика ограничений (App Policy):**
  - Максимум 5 смещений напоминаний на задачу (в диапазоне от 0 до 40320 минут).
  - Лимит в **50 ближайших хронологических будильников** во всей системе SanPlan.
- **Синхронизация без фоновых процессов:** расписание обновляется при открытии приложения, переходе на вкладку будильников, извещении веб-моста `plansChanged` и ручном pull-to-refresh с коалесценцией наложений.

## 2. Требования к оборудованию и ПО

- Компьютер **Mac** с установленной средой **Xcode 26** (или облачная сборка в GitHub Actions macOS Runner).
- Смартфон **iPhone** под управлением **iOS 26**.
- Кабель для подключения iPhone к Mac (или настроенное беспроводное подключение).
- Обычный персональный Apple ID (платный аккаунт разработчика за $99/год **не требуется**).

## 3. Пошаговая инструкция по сборке и установке на Mac

### Шаг 1: Открытие проекта в Xcode
1. Склонируйте репозиторий на Mac.
2. Убедитесь, что в директории `native/ios/SanPlan/` присутствует файл `PlanGateway.swift`.
3. Откройте проект в Xcode:
   ```bash
   open native/ios/SanPlan.xcodeproj
   ```

### Шаг 2: Настройка бесплатного профиля подписи (Personal Team)
1. В левой панели Xcode выберите проект **SanPlan**.
2. Выберите цель (Target) **SanPlan**, затем перейдите на вкладку **Signing & Capabilities**.
3. В выпадающем списке **Team** выберите вашу личную команду (**Personal Team**).
4. В строке **Bundle Identifier** при необходимости укажите уникальный идентификатор, например:
   `com.yourname.sanplan.companion`
5. Xcode автоматически создаст бесплатный профиль подписи (Free Provisioning Profile на 7 дней).

### Шаг 3: Включение режима разработчика на iPhone
1. На подключенном iPhone откройте:
   **«Настройки» → «Конфиденциальность и безопасность» → «Режим разработчика» (Developer Mode)**.
2. Переведите переключатель в положение **Включено** и подтвердите перезагрузку устройства.
3. После перезагрузки разблокируйте телефон и подтвердите включение режима разработчика.

### Шаг 4: Запуск на устройстве
1. В верхней панели Xcode в списке целевых устройств выберите ваш физический iPhone.
2. Нажмите сочетание клавиш **Cmd + R** (или кнопку Run).
3. При первом запуске на iPhone перейдите в **«Настройки» → «Основные» → «VPN и управление устройством»**, выберите ваш Apple ID и нажмите **«Доверять»**.
4. Запустите приложение SanPlan на iPhone.

## 4. Чек-лист проверки на реальном оборудовании (Lockscreen Test)

Для подтверждения корректной работы AlarmKit выполните следующие шаги:

1. **Разрешение доступа:**
   - Перейдите на вкладку **«Будильники»** и нажмите кнопку **«Разрешить доступ»**.
   - В системном окне iOS подтвердите разрешение SanPlan на установку будильников.
2. **Диагностический тест через 1 минуту:**
   - Раскройте секцию **«Диагностика AlarmKit»** внизу экрана и нажмите **«Проверка через 1 минуту»**.
   - В панели статуса отобразится сообщение об успешной установке сигнала.
3. **Блокировка экрана:**
   - Заблокируйте iPhone боковой кнопкой питания.
   - Выгрузите приложение из списка задач (swipe up).
4. **Срабатывание и отключение:**
   - Ровно через 60 секунд на заблокированном экране появится системный полноэкранный интерфейс AlarmKit со звуком и фиолетовым акцентом.
   - Нажмите кнопку **«Закрыть»** (Stop).
5. **Сверка после срабатывания:**
   - Разблокируйте телефон и откройте SanPlan.
   - Убедитесь, что отработавший тестовый сигнал автоматически удален из списка без сообщений об ошибках.
6. **Проверка нескольких смещений и завершения задач:**
   - В веб-интерфейсе добавьте задачу с несколькими смещениями (например, за 0, 15 и 60 минут).
   - Нажмите кнопку обновления на вкладке будильников и убедитесь, что создано соответствующее число сигналов с информативными заголовками.
   - Отметьте задачу выполненной и проверьте, что связанные будильники автоматически сняты.

## 5. Модульные тесты и статус проверки на Windows / macOS

### Тестирование через инъекцию (Dependency Injection)
`AlarmCoordinator` поддерживает протокол `AlarmServiceProtocol` и изолированные хранилища `UserDefaults`. Тестовый набор `NativePlanTests.swift` включает полную проверку сценариев сверки:
- `testStoppedMissingStaleCleanup`: штатная очистка сработавших сигналов.
- `testCancellationStillPresentFailurePreservesAndReports`: сохранение записи при ошибке снятия и вывод понятного названия задачи.
- `testCancellationRaceAbsentConfirmedRemoves`: корректное снятие при гонке, когда сигнал уже удален из системы.
- `testMissingDesiredFutureRestoredWithoutDuplicates`: восстановление потерянных сигналов без дубликатов.
- `testPlanRenameReschedulesAlarm`: пересоздание будильника при переименовании задачи.
- `testRescheduleOrCompletedCleanup`: удаление будильников при завершении задачи.
- `testSystemEnumerationFailureRetainsRegistry`: сохранение локального реестра при сбое чтения системы.
- `testFormatSystemAlarmTitle`: проверка включения названия задачи, времени и смещения в заголовок.

### Верификация на Windows vs macOS
- На платформе **Windows** компиляция кода Swift и запуск XCTest технически невозможны из-за отсутствия SDK Darwin/Xcode. Для проверки целостности структуры проекта на Windows используется скрипт:
  ```bash
  node scripts/verify-native-project.mjs
  ```
  Статус `nativeCompiled: false` в отчете скрипта на Windows является честным техническим отражением окружения.
- Полноценная компиляция ARM64, сборка IPA и запуск тестов XCTest выполняются в среде **macOS CI (GitHub Actions)** на Xcode 26+.
